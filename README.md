查询宿舍电表的**剩余电量、已用电量、已购电量**，拉取**每一笔充值记录**（精确到秒），
按充值账号做备注、按人汇总、导出 Excel / Markdown，支持**定时日报**与**充值到账提醒**，
并自带一个 Web 控制台：选楼栋房间、看用电趋势、按时间范围查询、备注管理、导出、手动推送。

> 仓库里不含任何个人数据：没有写死房间号、群号、QQ 号或昵称。
> 房间由使用时从平台拉取的列表里选，推送目标由插件运行时向机器人查询得到。

---

## 一、数据来源

学校使用的是一套第三方「宿舍电表缴费」平台（前端为 H5 页面，后端为统一网关）。
该平台对每个房间以一串内部编码定位，而不是房间号本身。

插件不模拟人工点击页面，而是**按平台自己的协议直接调用它的查询接口**——因此速度快，也不需要浏览器。

平台只返回两个累计值：**累计已用电量** `elecUsed` 与**累计已购电量** `elecBuy`，
剩余电量 = 已购 − 已用，插件不做估算。平台没有「某一天的读数」这种历史接口，
所以区间数据靠本地每日记录与充值台账推出来，见下文。

## 二、请求协议

平台把每个请求都包装成同一种信封：

| 字段 | 含义 |
| --- | --- |
| `appid` / `appsecret` | 平台下发给前端的应用标识（前端代码里可见） |
| `biz_data` | 业务参数，**用 RSA 公钥加密后**再放进信封 |
| `biz_encryption` | 固定 `RSA` |
| `sign` | **MD5 签名**：信封字段按 key 排序后拼上 `appsecret`，取大写摘要 |
| `timestamp` / `requestid` | 毫秒时间戳与随机请求号 |

即：**业务参数先加密，整封信再签名**。

关于密钥来源，如实说明：`APPID`、`APPSECRET`，以及 `elec_core.py` 里那一对
**RSA 公钥 + 私钥**，全部来自该缴费平台自己的**微信小程序前端包**。小程序把它们打包进客户端，
任何安装者本地都能提取——这是平台前端的既有设计，不是本插件另配的凭据。插件只是复刻小程序
原本的请求/响应流程：公钥加密发出去的 `biz_data`，私钥解密平台返回的 `biz_data`（服务端用同一对密钥，
所以客户端也带着私钥）。

这一对密钥只用于**这一个公开电费接口的信封加解密**，与用户账号、微信登录态、校园统一身份认证都无关；
插件不读取、不保存任何登录凭据。平台轮换密钥后插件会失效，届时需按新版小程序前端重新提取。

## 三、房间定位

平台内部用「楼栋编号 + 房间编号」定位，房间编号 = **楼栋号 + 房间号** 拼接。
插件拉取全校房间清单并缓存（控制台点「查询」即刷新），你只需从下拉里选**楼栋**和**房间**，
插件自动换算成平台内部编号，**不需要填任何内部 ID**。

配置项里保留 `loudong_no` / `room_no` 两个纯数字字段（便于脚本化部署），但正常用法是在控制台里选——
手填容易填到平台查不到的房间。

## 四、安装

1. 把整个插件文件夹放进 AstrBot 的插件目录（`data/plugins/` 下）。
2. 重启或重载插件。
3. 打开 AstrBot 管理面板 → 插件 → **无锡科技职业技术学院宿舍电费查询** →
   打开「电费控制台」，点「查询」选楼栋与房间，保存即可。

> 依赖：`cryptography`（加解密）、`openpyxl`（导出 Excel）。AstrBot 自带环境通常已包含；
> 若缺失只影响导出，其余功能不受影响。

## 五、指令

| 指令 | 说明 |
| --- | --- |
| `/电费` | 查询当前房间的剩余电量与已用 / 已购电量 |

指令可在**任意会话**（任意群、任意私聊）里使用，结果回到发起指令的会话。

## 六、Web 控制台

打开插件页面「电费控制台」，从上到下七块。

### 1. 当前房间

五张卡片：**剩余电量 / 已用电量 / 已购电量（按默认开始时间）/ 已用比例 / 全部已用电量（附今日用量）**。

- 区间用电有两条路子：① **电表读数做基线**（`hist.json` 每天记读数，默认开始时间那天有读数就用「当前累计 − 基线」）；
  ② **充值台账反推**（区间购电 = 区间充值 ÷ 固定电价，区间用电 = 区间购电 − 当前余额）。
  卡片小字会写明当前用的是哪条：`自 <区间起点> 起 · 按 <电价> 元/度 由 N 笔充值（合计 X 元）推算`。
  反推假设「区间起点余额为 0」（宿舍开户表底为 0），若账户本来就有历史余额，算出来的用电量会略偏低。
  结果缓存 180 秒，避免每刷一次首页都拉几百条充值记录。
- 没有更早基线时，卡片会明确写「平台只给累计读数，缺该日期的读数，这段区间算不出」，不拿累计值冒充分段值。
- 剩余电量低于阈值会变色提示，下面一行小字标明**数据更新于**的年月日与时分秒。
- **「预计使用时间」**：日均 = **用电趋势图里过去几天的日用量取平均**（今天没走完，不计入），
  与趋势图完全同源，所以两处数字不会打架。卡片小字写成 `近 N 天日均 XX.XX 度 · 预计 X月X日用完`。
  完全没有日用量数据时才退回昨天单日用量。

### 2. 用电趋势

一张折线图（带面积底色），右上角四个按钮切换范围：

| 按钮 | 粒度 | 说明 |
| --- | --- | --- |
| **近 12 小时**（默认） | 每 30 分钟一个点 | 24 个点，近半天的用电形态 |
| 近 24 小时 | 每小时一个点 | 24 个点 |
| 近 7 天 | 每天一个点 | 7 个点 |
| 近 30 天 | 每天一个点 | 30 个点 |

- 数值取平台返回的**累计用电量**，相邻两次采样相减得到区间真实用电——充值不会让曲线跳变，也不需要拿充值记录对账。
- 采样由后台**每 30 分钟自动完成一次**（配置项 `sample_interval`，默认 1800 秒，设 0 关闭），查询房间时也会顺带补一个点，
  **4 分钟节流**后写进 `samples.json`，保留 35 天。
- **缺数据的时段**：折线**直接跨过去不断开**（前后两端都是真实读数），该位置底部标一个灰点，悬停显示「无采样数据」。
- **近 7 天与近 30 天装上就能看**：优先用已有的每日记录回填；日视图、24 小时、12 小时与「预计使用时间」的日均
  全部走同一份合并序列（`samples.json` + `hist.json`），四处数字互相自洽。
- 标题右侧显示所选范围的 `合计 XX.XX 度 · 峰值 XX.XX 度 · 谷值 XX.XX 度`，切换范围时同步刷新。
- 图上的**数值直接标在数据点上方**，不用悬停也能读；悬停可看到具体时段与度数。
- **X 轴刻度**：近 12 小时标每个整点、近 24 小时标每 2 小时一个整点（共 12 个）、
  近 7 天标每一天、近 30 天每 5 天标一个日期。
- 图表为手写 SVG，**不引入任何外部图表库**。

### 3. 房间设置

**默认收起**，点标题展开、再点收起。

- 最左是**「查询」按钮**：从平台拉取可选楼栋与房间填进下拉框（缓存 5 分钟）。
- **楼栋、房间只能从下拉里选**，不能手输，从源头避免填到查不到的房间。
- 选好点「保存房间」，立刻按新房间重新解析并刷新首页数据。
- 界面上不出现「小区 / 校区 ID」「数据源」这类内部参数，插件用固定默认值处理。

### 4. 通知设置

**默认收起**，点标题展开、再点收起。

- 每日推送时间（逗号分隔，24 小时制）、低电量阈值、充值监控间隔；
- 推送目标按**群聊（N）**与**私聊（M）**分行显示，条数在行首，名字多时自动换行，不挤成一团；
- 「检测可用会话」重新探测群聊与私聊；
- 两个开关：启用定时推送、启用充值监控；
- **未选中任何目标时不主动发送**，不会乱发到默认会话。

### 5. 充值记录查询

- 最左**「默认开始时间」按钮**：弹窗选时刻，确认后每次打开控制台都从该时刻开始查；
  旁边的「开始时间」输入框可临时手改，只影响当前这一次。
- 结束时间留空 = 自动取到最新；右侧三个快捷键：**本周 / 近30天 / 开学至今**。
- 操作栏：导出 Excel、导出 Markdown、推送日报、推送充值提醒、刷新数据
  （有未同步改动时「刷新数据」变橙色带圆点）。

### 6. 三个视图

**每人总金额表** / **充值明细表（总表）** / **个人充值记录**。
表格里可直接改备注（失焦即保存），表格与通知都会带上备注列。

备注框右边的小眼睛：**睁眼显示备注名，闭眼显示原始账号**（闭眼时只读，再点恢复编辑）。

### 7. 运行日志

页面最下面一块，**默认收起**。用来回答两个问题：通知发出去没有、运行时报了什么。

- **插件日志**：进程内保留本插件最近若干条，四个按钮切换 **全部 / 正常 / 警告 / 错误**。
  选「全部」时**正常**级别折成一行「正常 N 条（点击展开）」，点开才逐条显示。
  每条带时间、级别、内容与源码行号。
- **已发送通知**：每次推送的时间、类型、成功与失败的目标数，点开可看当时发出的完整正文。
  这部分**落盘保存**（`notices.json`），重启后仍可查；插件日志只在进程内保留。

两个列表都只读，不改动任何数据。

## 七、通知

推送前一律先预览，确认后才真正发送。

- **定时日报**：默认每天 08:00 与 20:00，可改成任意时刻（逗号分隔）。可改标题，可勾选显示项：
  剩余电量 / 昨天用电 / 累计用电与购电 / 预计使用时间 / 本月已充金额 / 低电量提醒。
- **充值到账提醒**：后台每隔若干秒比对一次充值记录，发现新记录立刻推送，固定格式（时间只到秒）：

```
💰 充值提醒    YYYY-MM-DD
💵 充值金额：XX.XX 元
🕐 充值时间：HH:MM:SS
👤 充值账号：备注 XXXXX
🧾 充值订单号：XXXXXXXX
🏠 充值房间：X号楼 XXXX室
🔋 电量剩余：XXX.XX 度
```

- 预览弹窗里可按账号粗筛、**逐条勾选要推哪几条**（带全选 / 全不选）、按充值时间倒序、最多展开 10 条
  （超出会在标题旁注明「另有 N 条未展开」，但**合并与推送范围仍是全部选中记录**）。
- **「最近充值」**：按最新那一天取记录，把当天**所有人**的充值一次性选中；
  **「上次充值」**：切到上一个有记录的日期，可连点往前退。
- 勾**「合并成一条消息发送」**把选中的多条合成一条发出，避免刷屏；合并时头部只出现一次，每笔只留金额 / 时间 / 订单号。
- 关闭预览会立刻停止这次预览：在途请求回来后直接丢弃，不再往弹窗里写内容。
- 金额、时间、订单号来自服务端实时数据，不可修改。

## 八、配置项

插件配置页（面板表单）和控制台改的是**同一批配置键**：

| 键 | 含义 |
| --- | --- |
| `loudong_no` / `room_no` | 楼栋号 / 房间号（建议在控制台选，别手填） |
| `notify_enable` / `notify_times` / `notify_targets` | 定时推送开关、时刻、目标 |
| `recharge_watch` / `recharge_interval` | 充值监控开关与间隔（秒，默认 300） |
| `sample_interval` | 趋势采样间隔（秒，默认 1800 即 30 分钟），设 0 关闭后台采样 |
| `low_threshold` | 低电量阈值（度） |
| `elec_price` | 固定电价（元/度，默认 0.55），用于充值台账反推度数 |
| `default_start` | 默认开始时间 |
| `show_left` `show_delta` `show_total` `show_forecast` `show_recharge` `show_warn` | 日报显示项 |
| `napcat_url` / `napcat_token` | NapCat HTTP 地址与令牌（可选） |

**同步机制**：AstrBot 面板保存配置只写文件，而插件读的是内存副本。插件在每次查询、保存、后台调度前
都会检查配置文件 mtime，发现变化就重新载入。所以在面板改配置**不需要重载插件**；在控制台保存会先同步
面板的最新改动再写入，**不会覆盖面板里刚改过的值**。

## 十、安全设计

插件的行为边界很窄，逐项列出便于审查与自查。

**出网目标只有两个**

| 目标 | 用途 |
| --- | --- |
| `https://pay.wxstc.cn/grdp-ele-third-unite` | 学校缴费平台的电费查询接口，唯一的业务请求 |
| `127.0.0.1:3000`、`127.0.0.1:3001`、`host.docker.internal:3000` | 本地 NapCat 的 HTTP 接口，仅发布消息时使用 |

除此之外没有任何地址：没有遥测、没有更新检查、没有 CDN、没有第三方统计。
NapCat 地址可用 `napcat_url` 或环境变量 `NAPCAT_URL` / `NAPCAT_HTTP` 覆盖，但只会连到你指定的地址。

**不做的操作**

- 不执行 `eval` / `exec` / `__import__`，不反序列化 `pickle` / `marshal`；
- 不起子进程，不调 `os.system`，不需要 `sudo`，不做容器探测与提权；
- 不读写 AstrBot 数据库，不修改模型上下文，不注册全局钩子；
- 除上述两个可选地址外，不读取任何环境变量。

**线程模型**

`elec_core.call()` 用 `urllib.request.urlopen`（同步阻塞）。所有可能触网的同步方法
（`_room` / `_room_json` / `_balance` / `_room_tree` / `_report_text` / `_napcat_call` /
`_fetch_recharge` / `_sample_poll` 等）在协程里**一律通过 `await asyncio.to_thread(...)` 调用**，
包括把它们作为实参传递的场合——实参不会被提前在事件循环里求值。首屏 `overview`、`/电费` 指令、
充值监控都整块下沉成单个同步函数，一次线程调用取全量数据，不留「算了一半」的漏洞。
`_where()` 只读缓存，未命中就用配置拼名字，**绝不为了显示名称去发网络请求**；`_room()` 用
`threading.Lock` 双检，冷启动也只拉一次清单；`initialize()` 起一个预热任务在线程里预取房间。

发版前有静态自检脚本用 AST 遍历全部 `async def`，只要协程体内出现未包 `to_thread` 的阻塞调用就报错。

**数据边界**

插件写入的所有文件都在 `data/plugin_data/astrbot_plugin_wxsc_elec_bill/` 下，
不碰插件目录之外的任何路径。

**下载接口防目录穿越**

`/download` 只接受文件名：先 `os.path.basename()` 掐掉路径部分，再拼到 `export/` 下，
最后 `os.path.isfile()` 确认存在才返回。`../`、绝对路径、软链接都取不到目录外的文件。

**日志**

统一 `from astrbot.api import logger`，不把请求体、令牌或密钥写进日志。

`import logging` 只用于让 `_RingHandler` 继承 `logging.Handler`、使用 `logging.Formatter`；
不调用 `logging.basicConfig()`，不动 root logger，不设置全局级别，也不注册任何文件或网络 handler。

控制台的「运行日志」需要在进程内留一份副本，所以给插件 logger 挂了一个**只读的内存环形缓冲**
（`_RingHandler`，最多 600 条）：只把已产生的日志抄一份进内存，不改级别、不写文件、不发网络请求；
重载插件时先摘掉旧 handler 再挂新的，不会越积越多。

## 十二、隐私、风险与免责

### 1. 隐私

插件只读取缴费平台对**本房间**公开的余额与充值记录。充值记录中平台本身不返回姓名、手机号或任何
可识别信息，插件也不会去推断或收集。账号备注由使用者自行填写，**仅存本地**，不会回传平台。

插件不含任何统计、埋点或远程上报；所有数据只在本机与平台之间往返。

### 2. 接口风险（请务必读完）

`elec_core.py` 里的 `APPID`、`APPSECRET` 与那一对 RSA 密钥，是通过**分析该缴费平台自己的微信小程序
前端包**得到的——属于对该接口的逆向复刻，不是学校或平台授权下发的开发者凭据。这意味着：

- **平台一旦轮换密钥或调整协议，插件会直接失效**，且不会提前通知。失效后需要按新版小程序前端重新提取，
  我无法保证能及时跟进；
- 平台若认定这类第三方调用违反其服务条款，可能封禁、限流或要求下线本插件；
- 所以**不要把本插件当作缴费或查询的唯一渠道**：金额与电量一律以平台页面显示为准，
  涉及欠费、退费、账目争议时，请以学校后勤或平台的正式记录为准。
